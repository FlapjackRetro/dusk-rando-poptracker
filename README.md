# DUSK Archipelago — PopTracker pack

Map tracker for the [dusk-rando](https://github.com/FlapjackRetro/dusk-rando) Archipelago world (apworld 0.4.x),
for [PopTracker](https://github.com/black-sliver/PopTracker) 0.25+.

## Install

Download `dusk_ap_tracker_<version>.zip` from the Releases page and drop it (still zipped) into PopTracker's `packs`
folder (usually `Documents\PopTracker\packs`), then pick **DUSK Archipelago** from the pack list. Click the **AP**
button to connect to your Archipelago server; items, checked locations, enabled episodes and check categories, and
the goal are all set automatically.

PopTracker checks this repo for new versions when the pack loads (from 0.2.0 on) and offers to download and
install them. The first time, it asks whether to load update information from `raw.githubusercontent.com`.

## What's in it

* **One map per level** (33), tabbed by episode. Maps are rendered top-down from the game's own level geometry and
  textures. Levels that stack on themselves are split into **layers** by height (lowest at the bottom); each layer
  only shows floors in its height range, so basements, upper floors and catwalks don't hide each other.
  Small, far-off groups of checks get their own **detached area** panel.
* **Every check** (3,183; Thermal Suits are never checks, and developer-only pickups the apworld leaves out aren't either) placed at its in-game position. Checks within a few pixels
  of each other share one pin; hover it to see each one. The **Level Complete** check has its own pin (marked
  EXIT) on every way out of the level: end-level buttons and walk-in loading zones. Levels with two exits get two
  pins for the same check. E3M10 has no exit, so its pin (marked BOSS) is over the final boss.
* **Map follows you**: while connected, the map tab switches to the level you load into (and to the episode tab on
  an episode's map screen). Needs a DuskRando mod build that reports the current level (it writes the
  `dusk_level_<team>_<slot>` data storage key). Untick **AUTO MAP** in the Settings row to turn it off.
* **Category visibility**: pins for categories that aren't randomized in your seed are hidden
  (Settings row; set from slot data, or toggle by hand).
* **Logic** mirrors the apworld:
  * a level is in logic with its Access item plus enough distinct firearms (combat logic table);
  * **key logic**: the apworld's per-location rules (`key_logic.py`: which checks need which keys, and extra items
    such as the Mortar for E3M1's Super Shotgun) are copied into the pack at build time; checks without a rule use
    strict key logic (all of the level's keys);
  * `combat_logic` is not in the apworld's slot data yet, so set the COMBAT item by hand (click to cycle
    exorcist → easy → normal → unhinged, as in the apworld; easy is the default). The pack already reads
    `slot_data["combat_logic"]` if the apworld adds it.

## Building detailed logic

`scripts/logic/regions.lua` is a workbench for replacing strict key logic level by level: define regions, what each
needs (keys, other regions, items), and which checks sit in which region. Any level you add there switches from
strict to region logic immediately (F5 reloads the pack), so you can watch the pins recolour as you collect keys.
The comments in that file show the format. Once a level is mapped, the same table translates directly into apworld
Regions + Entrances.

## Repository layout

The repo root *is* the pack (that's what PopTracker loads); `tools/` holds the generator and is left out of release
zips.

| Path | Hand-written or generated |
|---|---|
| `manifest.json`, `scripts/init.lua`, `scripts/logic/logic.lua`, `scripts/logic/regions.lua`, `scripts/autotracking.lua`, `scripts/autotracking/archipelago.lua` | hand-written |
| `items/`, `locations/`, `maps/`, `layouts/`, `images/`, `scripts/logic/data.lua`, `scripts/autotracking/{item,location}_mapping.lua` | generated by `tools/build_pack.py` — edit the generator, not these |

See [tools/README.md](tools/README.md) for regenerating maps (e.g. after a dusk-rando `locations.json` change) and
for per-level map tweaks.

## Releasing

1. Bump `VERSION` in `tools/build_pack.py` and run `python tools/build_pack.py` (writes `package_version` into
   `manifest.json`).
2. Add the new version at the top of `versions.json` with its `changelog` lines (or let step 3 create the entry and
   fill the changelog in afterwards).
3. `python tools/package.py` builds `dist/dusk_ap_tracker_v<version>.zip` and writes that zip's sha256 and release
   download URL into `versions.json`.
4. Commit and push (`versions.json` on `main` is the update feed PopTracker reads), then create the GitHub release
   tagged `v<version>` and upload **that exact zip**. PopTracker rejects an update whose sha256 doesn't match, so don't
   rebuild the zip after step 3; if you do, run `package.py` again and commit the new hash.

Players get the update offer the next time they load the pack.
